# QUINTUM Exchange Listing Requirements Register

Status: **LIVE DOCUMENT — PRE-MAINNET**  
Last external-source review: **2026-10-04**  
Purpose: maintain a current, exchange-by-exchange record of what major centralized exchanges publicly request before listing review.

This file records public requirements and review signals only. It does **not** claim that QUINTUM is currently eligible for listing. Mainnet is not launched and production deposits/withdrawals must not be enabled.

## Operating rule

Before any application is submitted:

1. re-open the official listing page for that exchange;
2. confirm that the application URL and requirements have not changed;
3. complete the QUINTUM master application using current facts only;
4. keep legal/KYC/private-team data out of the public repository;
5. submit only through the exchange's official channel;
6. independently verify any person claiming to represent the exchange;
7. record submission date, evidence package version and subsequent requests in a private listing log.

## Common information that must always be ready

The following package is maintained for every exchange:

- project name, network name and final ticker;
- Layer-1 / native-asset classification;
- concise project description and use case;
- official website and source repository;
- whitepaper / protocol specification;
- team and responsible-contact information for private due diligence;
- legal entity information if/when one exists;
- launch history and development provenance;
- Mainnet Genesis data and exact network parameters;
- consensus algorithm and chain-selection rules;
- supply, issuance, block reward, halving and premine disclosure;
- token/coin distribution and circulating-supply methodology;
- node source, reproducible builds and release hashes;
- block explorer;
- exchange node installation and upgrade guide;
- RPC/API specification;
- deposit address format;
- transaction format and fees;
- recommended deposit confirmations;
- reorganization/finality risk guidance;
- wallet backup/recovery information;
- security architecture and third-party audit reports when available;
- market/community metrics with dated evidence;
- existing markets and liquidity information once applicable;
- regulatory/legal analysis for requested jurisdictions;
- MiCA whitepaper package where EEA listing requires it;
- official branding package;
- technical and business emergency contacts.

- audited security evidence;
- adoption/network statistics;

### Kraken EEA / MiCA

Kraken states that EEA listings require a MiCA-compliant whitepaper. Its current guidance states that, under the applicable implementation timeline, the whitepaper must be produced in XBRL and submitted to a National Competent Authority in advance of the intended listing date.

QUINTUM package items to have ready:

- full technical due diligence;
- Mainnet explorer;
- production node/RPC;
- launch and distribution history;
- community/on-chain metrics;
- legal/compliance package;
- MiCA XBRL whitepaper + explanatory notes for an EEA route.

## Exchange-independent blockers before serious applications

The following are currently mandatory project gates regardless of exchange:

- Mainnet consensus freeze;
- final Mainnet ticker decision;
- actual Mainnet launch;
- multiple independent public seed/full nodes;
- DNS/bootstrap production infrastructure;
- production block explorer;
- stable and documented exchange RPC/API;
- deposit/withdraw integration tests;
- final recommended confirmation policy backed by reorg testing;
- signed release artifacts or an equivalent production release-signing process;
- independent third-party security review;
- public vulnerability/security-contact policy;
- legal/regulatory review for intended listing jurisdictions;
- final whitepaper;
- final supply/circulating-supply methodology;
- sufficient real network/adoption history to support exchange due diligence.

## Maintenance cadence

This register must be reviewed:

- before every exchange application;
- after any exchange materially changes its public listing process;
- after QUINTUM Mainnet parameters change;
- after any consensus/security/networking change that affects integration;
- at least monthly while the project is approaching Mainnet/listing readiness.

All source reviews must be dated. Requirements observed from unofficial agents, paid "listing brokers" or unverifiable messages are not accepted as authoritative.

# QUINTUM Android

QUINTUM Android is a native mobile client built around the existing C++23 QUINTUM Core. Android does not define a second consensus implementation.

## Runtime model

The target runtime is:

```
Jetpack Compose / Kotlin
        |
Android lifecycle and foreground services
        |
authenticated loopback JSON-RPC
        |
ARM64 QUINTUM C++ Core
        |
P2P / chainstate / wallet / RandomX
```

The first supported ABI is `arm64-v8a`. Additional ABIs require the same consensus and RandomX test vectors before release.

## Networking

Android participates as an outbound P2P node. Desktop UPnP/NAT-PMP port mapping is compiled out on Android; carrier and mobile NAT environments cannot be treated like desktop routers. This does not change wire protocol, peer discovery, block/transaction relay or consensus.

RPC remains bound to loopback and uses the per-run cookie generated by QUINTUM Core.

## Mining

RandomX remains the consensus implementation from the C++ Core and its pinned upstream revision. Mobile mining will be explicit, foreground, stoppable and resource-controlled. Android UI code must never simulate accepted shares, blocks or hashrate.

## Compatibility

Android work must not change Genesis, network magic, address encoding, ports, monetary policy, transaction serialization, wallet format or RandomX consensus behavior.

See `android/UPDATE_SECURITY.md` for the update contract.

### AND-003 — Thermal stop blocked Android UI (2026-10-08)

- Cause: `MiningController.snapshot()` synchronously called JNI `nativeStopMining()` when the device overheated. Native stop joins the mining thread, potentially blocking the Compose UI.
- Fix commit: `56b4113063a39e36bf74f1d96e98375602ffef1a` dispatches thermal stop to an IO coroutine and avoids repeated stop requests during a running mining session.
- Verification: **PENDING** Android CI and on-device thermal/stop/restart testing. Review concurrency of manual stop and thermal stop before release.
- Compatibility: Kotlin lifecycle only; no consensus, wallet, address, or network changes.

### AND-004 — ARM64 shared-library link fails without PIC (2026-10-08)

- Evidence: Android CI run 37722847058, job 113134253738; linker `ld.lld` reported `R_AARCH64_ADR_PREL_PG_HI21` / `R_AARCH64_ADD_ABS_LO12_NC` relocations and `recompile with -fPIC` while linking `libquintum_android.so`.
- Root cause: static C++ Core and dependency objects were not guaranteed to be position-independent when linked into the Android JNI shared library.
- Fix commit: `d693848a35e22bc352882d1eb81f6c55fcabc8d0`; CMake enables `POSITION_INDEPENDENT_CODE` for `quintum_core`, `monocypher`, and `randomx` only in the Android configuration.
- Verification: **PENDING** clean ARM64 compile/link, Android unit tests, APK packaging and device smoke test. Keep this issue open until the checks pass.
- Compatibility: build flags only; no consensus or wallet format changes.
